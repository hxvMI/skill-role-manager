# Candidate responsibility mappings and minimal routing

These are single-session responsibilities and instruction-driven selection guidance, not running agents, native discovery configuration or background automation. Applicable instructions and existing task authorization take priority. Use only relevant procedures; for simple tasks answer directly. No role grants tools, delegation or mutation authority.

| Role | Responsibility and procedure selection | Boundary/output |
|---|---|---|
| Knowledge Keeper | context-engineer selects context; knowledge-maintainer reconciles durable records; session-handoff preserves continuation | Evidence-linked packet/authorized records; no master-rule or disputed-fact change without review |
| Verifier | scenario-tester executes approved checks; independent-audit challenges claims; visual-fidelity-reviewer compares actual visuals when relevant | Actual results/findings and missing gates; self-review never independent; no release authority |
| Continuous Improvement | root-cause-investigator diagnoses; existing automation-review assesses recurrence/metrics; existing skill-builder packages a proven process; skill-evaluator assesses it | Scoped proposed control with verified evidence; no automatic permanent rules or schedules |
| Orchestrator | existing project-workflow owns scoped implementation loop; existing grill-me-spec resolves consequential uncertainty | Select next authorized increment and minimal procedure; no new runtime, mandatory delegation or autonomous escalation |

| Request/need | Primary owner | Distinction |
|---|---|---|
| Consequential unclear feature/requirements | existing grill-me-spec | Before implementation; reuse settled answers |
| Bounded substantial implementation | existing project-workflow | Owns overall verify/fix/retest loop |
| Proven repeated process into a skill | existing skill-builder | Skill authoring, not evaluation |
| Project gates/metrics/recurring incidents | existing automation-review | Does not invent recurrence or schedule itself |
| Reconcile facts/decisions/stale records | knowledge-maintainer | Durable-record changes under approved write boundary |
| Prepare relevant context or expose conflicts | context-engineer | Select context, do not edit source to reduce it |
| Switch sessions or preserve resumable state | session-handoff | Temporary state; never claim automatic future reading |
| Assess a skill or its evaluation evidence | skill-evaluator | Assesses procedure/benefit; not general application tests |
| Execute approved requirement-linked checks | scenario-tester | Records actual behavior and gaps |
| Difficult/repeated failure with uncertain cause | root-cause-investigator | Test hypotheses; do not assume recurrence without records |
| Challenge correctness/architecture/claims | independent-audit | Reviewer provenance decides independence |
| Check rendered style against approved reference | visual-fidelity-reviewer | Needs actual reference/output and intended-change scope |

For ambiguous “review,” infer scope from available task context; ask only if a consequential choice remains. Combine procedures only for distinct work: diagnosis can hand frozen checks to testing; knowledge maintenance can hand temporary status to handoff. Keep one owner for shared files, reread before writing and do not simulate concurrency. A separate reviewer or agent must actually exist and be authorized before describing delegated or independent work.

Availability: the four existing skills are reused references, not copied into this candidate. The eight new sources are in skills/; the package file hashes are in manager.json. Missing procedures/tools require a disclosed fallback or blocker. Explicit source reading is not native activation. Rollback and adoption follow the existing governance gate; no propagation across projects.
